# Week 4 WP4-03 监控与历史执行计划

## 目标

补齐库存监控、看板监控、入库历史和出库历史，形成可查询、可追溯、可演示的 WMS 状态总览。

## 范围

- 当前库存监控，覆盖可用、锁定、封存、零头数量。
- 看板监控，覆盖生命周期状态和筛选。
- 入库历史和出库历史查询。
- 预警状态展示，包含低储、高储、缺货风险、呆滞风险的基础口径。

不做复杂 BI 报表、外部数据大屏和真实 AI 模型。

## 活动拆解

| 活动 | 内容 | 输入 | 输出 | 验收标准 |
| --- | --- | --- | --- | --- |
| ACT-01 指标口径 | 明确库存、看板、历史、预警字段口径 | 总体需求规格、现有库存服务 | 字段清单和筛选项 | 数量口径与业务规则一致 |
| ACT-02 后端查询 | 增加或调整监控/历史查询接口 | ACT-01 | 查询接口和 Mapper SQL | 支持主要筛选条件 |
| ACT-03 库存监控页 | 展示库存总览、筛选和预警状态 | ACT-02 | Web 库存监控页面 | 可查可用、锁定、封存、零头数量 |
| ACT-04 看板监控页 | 展示看板列表、状态、生命周期和详情入口 | ACT-02 | Web 看板监控页面 | 可按状态和业务字段筛选 |
| ACT-05 出入库历史页 | 补齐入库和出库历史查询 | ACT-02 | 历史查询页面 | 可按单号、物料、状态、时间筛选 |
| ACT-06 验证 | 测试、构建和联调 | ACT-02 至 ACT-05 | 验证记录 | 查询结果与流水一致 |

## 依赖

- 基础页面骨架可提前做。
- 封存数量、零头数量和散件历史字段依赖 WP4-01 的最终数据模型。
- 呆滞/缺货风险字段与 WP4-05 AI 预警口径共享。
- 移动端扫码结果追溯依赖 WP4-02 的联调路径。

## 验证

- 后端：`cd backend && mvn test`
- 前端：`cd frontend && npm test`
- 构建：`cd frontend && npm run build`
- 联调：入库、锁库、封存、散件出库后监控与历史页面数量一致。

## 风险

- 如果 WP4-01 数据模型变更较大，监控查询需要二次调整。
- 预警口径容易与 AI 方向重叠，应先用规则型状态表达。
