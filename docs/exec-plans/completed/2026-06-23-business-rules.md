# Week 4 WP4-01 业务规则补全执行计划

## 目标

补齐封存/解封、手动锁库、散件出库、零头库存和 FIFO 修正，让当前箱级出库能力扩展为可处理人工库存干预和按件出库的业务闭环。

## 范围

- 新增人工封存/解封能力。
- 新增手动锁库/解锁能力。
- 支持散件出库和看板剩余数量。
- 调整 FIFO 校验，使其覆盖整箱和散件场景。
- 更新库存余额、看板状态、库存流水和审计记录。

不做完整质量审批流、财务核算、真实 PDA 设备协议。

## 活动拆解

| 活动 | 内容 | 输入 | 输出 | 验收标准 |
| --- | --- | --- | --- | --- |
| ACT-01 业务状态建模 | 梳理 `RECEIVED`、`LOCKED`、`SEALED`、`SHIPPED` 等状态转换，明确封存和锁库冲突规则 | 现有看板、锁货、出库服务 | 状态转换表和接口约束 | 规则能解释封存、解封、锁库、出库的互斥关系 |
| ACT-02 后端数据与接口 | 增加封存/解封、手动锁库/解锁接口和必要字段/表 | ACT-01 | Controller、Service、Mapper、迁移逻辑 | 被封存库存不参与普通出库和自动锁货 |
| ACT-03 散件出库 | 调整出库数量计算、看板剩余数量和库存扣减逻辑 | 现有出库 pick 服务 | 支持按件出库的事务逻辑 | 部分出库后剩余数量可查、可继续出库 |
| ACT-04 FIFO 修正 | 修改 FIFO 候选和违规处理，覆盖整箱与零头 | ACT-03 | FIFO 校验和错误提示 | 存在更早可用库存时能提示或阻断 |
| ACT-05 前端入口 | 在锁货、看板、库存页面加入封存、解封、手动锁库操作 | ACT-02 | Web 操作入口和反馈 | 页面可完成基本人工库存干预 |
| ACT-06 验证与债务记录 | 补测试、联调、更新债务 | ACT-02 至 ACT-05 | 测试记录和债务更新 | 后端测试通过或记录无法运行原因 |

## 依赖

- 依赖 `docs/specs/2026-06-17-lock-goods-design.md` 的既有锁货模型。
- 影响 WP4-02 手机端出库、WP4-03 监控历史、WP4-05 AI 预警字段。

## 验证

- 后端：`cd backend && mvn test`
- 前端：`cd frontend && npm test`
- 涉及路由或构建时：`cd frontend && npm run build`
- 手动联调：封存 -> 普通出库不可用 -> 解封 -> 可出库；散件出库后看板剩余数量正确。

## 风险

- 零头库存会改变既有整箱看板假设，需要避免破坏当前演示数据。
- 封存和手动锁库都属于人工库存占用，必须防止与出库单锁货重复占用。
- FIFO 违规是提示还是阻断仍需业务确认，未定时记录到产品债。
