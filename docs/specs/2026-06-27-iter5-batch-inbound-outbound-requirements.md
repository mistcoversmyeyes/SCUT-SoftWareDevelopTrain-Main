# Iteration 5 需求规格：批量出入库、FIFO 推荐、批量打印与手机端封存

## 背景输入

本规格服务于 Iteration 5 周迭代需求冻结。Iteration 4 已经完成入库、出库、库存标签、库存监控、手机端基础扫码、封存/解封和 FIFO 等能力的基础建设，但老师在后续需求沟通中提出了更偏操作效率和演示可用性的要求：

- 批量出入库要能根据供应商批量选择物料。
- 输入出入库物料数量后自动计算箱数和零头。
- 批量选择库位的逻辑需要设计。
- 出库不再以“释放并锁库”为主流程，而是由系统给出 FIFO 推荐，实际出库以人工扫码为准。
- 手机端应能直接处理后台创建的待处理出库单。
- 库存标签批量打印是重点能力。
- 库存详情页要更清楚展示物料和短缺情况。
- 手机端需要支持库存封存/解封。

本规格以当前 WMS 领域模型为基础，控制范围，不引入需要额外领域建模的转包、装包、拆包、合包、零头合并、自动库位分配或 AI 预警。

## 总体目标

- 提供批量入库创建流程，降低操作员逐条录入供应商、物料、数量和库位的成本。
- 提供批量出库创建与 FIFO 推荐方案，支持网页端和手机端按推荐或非推荐方式扫码出库。
- 在手机端 H5 展示待处理出库单列表，支撑仓库现场直接处理出库任务。
- 强化库存标签批量打印，使入库标签能按选中项或按入库单一次性打印。
- 增强库存详情页的短缺展示和供应商筛选，不与 AI 预警混淆。
- 在手机端 H5 支持扫码封存和解封库存标签。

## FR-01 批量入库创建

### 业务规则

- 批量入库的核心对象先是“待创建明细”，不是直接创建入库单。
- 用户通过多轮操作构建待创建明细：
  1. 点击“添加入库明细”。
  2. 选择供应商。
  3. 系统展示该供应商名下物料。
  4. 用户勾选物料并填写入库数量。
  5. 系统根据容器规格自动计算箱数和零头。
  6. 系统生成待创建明细。
  7. 用户为待创建明细批量设置或逐行设置目标仓库/库位。
- 每条待创建明细必须包含：
  - 临时明细序号
  - 供应商
  - 物料
  - 容器类型
  - 入库数量
  - 箱数
  - 零头
  - 目标仓库
  - 目标库位
- 目标仓库和目标库位是必填项；所有待创建明细完备后才允许最终提交。
- 相同供应商、相同物料、相同数量的多条明细不得自动合并。它们可能表示两包散件、两批到货或用户有意分开打印/扫码。

### 入库单生成规则

- 最终提交时，系统根据待创建明细生成入库单。
- 系统按供应商聚合生成入库单：
  - 不同供应商生成不同入库单。
  - 同一供应商下的多条待创建明细进入同一张入库单。
  - 同一供应商下重复物料仍保留为不同入库单明细行，不按物料或数量合并。
- 入库单是单据头，业务追踪粒度仍以入库明细行为准。
- 库存标签必须按入库单明细行生成，不得按整张入库单生成一个统一标签。
- 每个库存标签必须能追溯到：
  - 入库单号
  - 明细行号
  - 供应商
  - 物料
  - 数量
  - 容器类型
  - 箱号或标签序号
  - 目标仓库/库位

### 库位设置交互

- 物料和数量选择完成后，只进入待创建明细状态，不立即创建入库单。
- 库位设置阶段展示当前待创建明细列表。
- 用户可以勾选多条明细，将同一个目标仓库/库位应用到选中明细。
- 用户可以对个别明细单独修改目标仓库/库位。
- 本轮不做自动库位分配，系统不根据容量、混放规则或物料限制自动决定库位。

### 箱数和零头

- 批量入库明细复用现有入库单明细的容器类型和箱数/零头口径。
- 用户填写总件数后，系统根据物料绑定的容器规格自动计算：

```text
总件数 = 整箱数 * 每箱容量 + 零头
```

- 例如每箱 100 件，输入 230 件，则自动显示 2 箱、零头 30。
- 修改容器类型时，应按新容器规格重新计算箱数和零头。

## FR-02 批量出库与 FIFO 推荐

### 出库单创建规则

- 批量出库不是系统自动完成出库，而是批量创建出库需求。
- 供应商在批量出库中主要作为物料筛选条件，不作为出库单拆分主键。
- 用户可以多轮选择供应商，勾选该供应商下的物料并填写出库数量。
- 最终提交时，系统生成一张出库单。
- 出库单可以包含多个供应商来源的物料明细。
- 每条出库明细保留供应商、物料、数量、容器类型、箱数和零头等信息。

### FIFO 推荐主流程

- Iteration 5 出库主流程不再以“释放并锁库”为核心。
- 出库单创建后，系统基于当前库存和 FIFO 规则生成推荐出库方案。
- 推荐方案用于指导操作员出库，不提前锁死库存。
- 推荐方案至少展示：
  - 推荐库存标签码
  - 物料
  - 仓库/库位
  - 当前剩余数量
  - 本次建议出库数量
  - 是否包含零头
  - 推荐顺序
- 实际出库以网页端或手机端扫码结果为准。

### 非推荐出库确认

- 如果扫码库存标签属于推荐方案，系统直接执行出库。
- 如果扫码库存标签不属于推荐方案，系统弹窗提醒：

```text
当前出库库存标签不在推荐出库方案中，是否继续按非推荐方案出库？
```

- 用户确认后，系统继续执行出库。
- 用户取消后，系统不执行本次出库，返回扫码页面。
- 本轮不要求填写偏离原因，不新增专门的非推荐出库审计字段。
- 出库流水和出库历史仍记录实际出库结果。
- 已封存、已出完、已取消、物料不匹配或无可用剩余数量的库存标签仍按既有业务规则拒绝出库。

## FR-03 手机端 H5 待处理出库单

- 手机端 H5 出库入口仅用于现场扫码处理出库任务。
- 手机端只显示待处理出库单，不显示已完成或已取消单据。
- 待处理范围包括待出库、出库中和部分出库状态。
- 手机端出库首页展示待处理出库单列表，至少包含：
  - 出库单号
  - 出库用途
  - 创建时间
  - 明细数量
  - 待出库总数量
  - 状态
- 点击出库单后进入扫码处理页。
- 扫码处理页展示：
  - 出库单基本信息
  - 出库明细
  - FIFO 推荐方案
  - 已扫码出库进度
  - 剩余待出库数量
- 手机端与网页端使用同一套 FIFO 推荐和非推荐出库确认规则。
- 出库完成后，该单据不再出现在手机端待处理列表中。

## FR-04 网页端出库推荐与确认

- 网页端出库页面也必须展示 FIFO 推荐方案。
- 网页端允许按推荐方案出库，也允许人工确认后按非推荐方案出库。
- 当网页端输入或扫码的库存标签不属于推荐方案时，必须弹出与手机端一致的确认提示。
- 网页端和手机端的库存标签校验、非推荐确认、库存扣减、库存标签状态和出库历史更新必须保持一致。

## FR-05 库存标签批量打印

- Iteration 5 批量打印对象锁定为库存标签。
- 本轮不把入库单、出库单或拣货单批量打印作为重点范围。
- 系统支持两种库存标签批量打印入口：
  - 打印用户勾选的库存标签。
  - 按入库单一键打印该单全部库存标签。
- 两种入口复用同一套批量打印预览和打印模板。
- 每个库存标签打印成一张独立标签卡。
- 标签卡必须有明确打印边框。
- 标签卡至少展示：
  - 库存标签码
  - 二维码
  - 入库单号
  - 明细行号
  - 供应商
  - 物料编码
  - 物料名称
  - 数量
  - 目标仓库/库位
  - 容器类型
  - 箱号或标签序号
- 批量打印预览页应支持浏览多张标签并触发浏览器打印。

## FR-06 库存详情短缺展示与筛选

- 库存详情页面增强属于库存查询和展示优化，不属于 AI 预警或智能推荐。
- 本轮不引入机器学习、外部数据、需求预测或 AI 文案。
- 短缺状态复用物料基础资料中的 `lowStockQty` 字段，不新增数据库表或独立配置入口。
- 物料维护页面已有低库存阈值配置入口，库存详情页只负责读取阈值并展示判断结果。
- 短缺判断使用可用数量，不使用账面数量：

```text
availableQty <= lowStockQty => 短缺
availableQty > lowStockQty  => 正常
```

- 未配置 `lowStockQty` 的物料不参与短缺判断，页面可显示“未配置阈值”。
- 库存详情页应支持：
  - 展示短缺标识
  - 将短缺物料前置展示
  - 只看短缺物料
  - 按供应商筛选物料
  - 按供应商筛选短缺物料
- 页面仍应展示库存数量口径，包括可用数量、锁定数量、封存数量、手锁数量和库位分布。

## FR-07 手机端库存封存/解封

- 手机端 H5 新增“库存封存”入口。
- 该入口不是单纯查询页，允许实际执行封存和解封。
- 操作员可以通过摄像头扫码、图片识别或手工输入库存标签码。
- 扫码后系统展示库存标签信息：
  - 库存标签码
  - 物料
  - 当前仓库/库位
  - 剩余数量
  - 当前状态
  - 是否已封存
- 未封存库存标签提供“封存”操作。
- 已封存库存标签提供“解封”操作。
- 封存原因必填，备注可选。
- 操作人取当前登录用户。
- 解封只需要二次确认，不要求填写原因或备注。
- 手机端封存/解封复用网页端已有封存/解封业务规则和记录模型。
- 操作成功后，库存标签状态、库存可用数量和封存数量应同步更新。
- 已出库、已取消、无剩余数量或其他不可操作状态的库存标签不能执行封存/解封，并显示明确错误。

## 明确不做

- 不实现转包、装包、拆包、合包或零头合并。
- 不实现自动库位分配。
- 不实现复杂 FIFO 授权、原因分类或专门审计流程。
- 不实现 AI 预警、智能推荐、外部市场预警或真实模型训练。
- 不接入真实 MES、ERP、SAP、PDA、扫码枪、标签机或打印机协议。
- 不改变当前库存标签作为库存载体的基本模型。

## 产品债出口

- 转包、装包、拆包、合包、零头合并继续归入 `PD-005 Packaging`。
- 复杂 FIFO 授权、原因分类和专门审计流程继续归入 `PD-014 Outbound FIFO`。
- FR-08/FR-09 的 AI 预警或智能推荐返工继续归入 `PD-017 FR-08/FR-09 Rework`。
- 自动库位分配新增产品债 `PD-018 Auto Location Allocation`。

## 验收标准

- 批量入库可以通过多轮供应商选择构建待创建明细，所有明细设置库位后一次提交，并按供应商生成入库单。
- 同一供应商下多条明细进入同一张入库单，重复物料不自动合并；库存标签按明细行生成。
- 批量出库可以创建出库单并展示 FIFO 推荐方案。
- 网页端和手机端扫码库存标签不属于推荐方案时均弹出非推荐出库确认。
- 手机端只展示待处理出库单，完成或取消单据不显示。
- 库存标签支持打印选中项和按入库单打印全部标签，打印页每张标签有独立边框和二维码。
- 库存详情页能基于 `availableQty <= lowStockQty` 展示短缺状态，支持只看短缺和按供应商筛选。
- 手机端库存封存入口可扫码查询库存标签，并执行原因必填的封存和确认式解封。
- 未进入本轮范围的复杂业务均有产品债出口，不以隐含假设实现。
